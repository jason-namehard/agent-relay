# Agent Relay — 第一次文件交接

版本：`0.1.0-preview.10`。Windows 完整包从 [Release](https://github.com/jason-namehard/agent-relay/releases/tag/v0.1.0-preview.10) 下载并完整解压，运行 `gui/AgentRelay.Desktop.exe`。`TryDemo.cmd` 仅提供隔离样本，不调用模型。GUI/通知自带运行库，CLI/MCP 需要 .NET 10 runtime；保留随包许可证。

## 最短路线

1. 在 Agent 管理中添加 A、B，名称由你决定，不必先解决 CLI。
2. 可选“安装交接规则”：选择该宿主实际加载的 `AGENTS.md`、`Agent.md` 或其他指令文件，查看规则并确认。常驻只有一行，详细说明按需读取；触发依赖宿主遵从，已有会话可能需重新读取指令。
3. 对 A 说清“写什么文件给谁”。装有规则时 A 可直接返回交接 JSON；未装时，把“新建交接 → 复制交接格式”附在要求后面。
4. 将 A 的 JSON 粘贴进新建交接，点击“解析并创建交接”。也可手动选择发送方、接收方、已存在文件及一句工作要求。新文件交接当前只支持手动传递提示。
5. 在任务详情点击“复制提示词给 B”，粘贴到 B。短提示指向任务上下文，B 读取文件、处理后按模板写回执。
6. 软件打开时自动读取回执变化；启动或刷新会补读。无需再选择“导入已完成回稿”。如果 B 结束工作且不需 A 继续，任务完成；如仍需 A 处理，软件会明确提示复制给 A。

交接 JSON 使用已登记 ID 或唯一名称，文件必须真实存在且为完整路径。完整格式见 [配置与回执](CONFIGURATION_ASSISTANT.md)。

## 看懂状态

| 状态 | 下一步 |
| --- | --- |
| 等待某个 Agent 接收并回复 | 复制提示词给显示的接收方 |
| 某个 Agent 已接收/正在处理 | 等它写回执，不重复创建任务 |
| 等待对方继续 | 按显示的下一步工作复制提示给该 Agent |
| 已完成 | 无需礼貌回传或重复确认 |
| 失败、超时或达到轮次上限 | 查看原因，人工判断是否重建 |

回执中的 `needs_reply` 决定是否还有必要工作。要求对方继续时必须有回稿文件与具体 `next_action`；最多四轮，防止反复确认或闲聊。文件改变不等于完成，只有有效回执才改变处理状态。

## 文件、迁移与卸载

外部交接文件复制进受管目录，原件保留；已受管文件直接复用，不再制造正文包装文件和重复结果快照。任务上下文与回执位于隐藏 `.relay` 子目录。最终成果仍应放在项目目录，过期受管文件通过清理操作删除。

迁移前必须完成或取消全部活动任务，包括等待对方继续的回传。更换中转站会复制当前站点文件与账本，校验后切换；保留日期沿用，旧站仅作备份，不会自动清理旧站。没有待完成迁移时，“迁移校验”会说明未发起迁移，不代表刚刚迁移成功。失败后解除文件占用，再用迁移校验继续。

稳定的按需指引入口在迁移后更新；已复制出去的旧短提示需要重新复制。删除便携软件前，先在设置“移除全部交接规则”，或执行 `relay --home <目录> guidance remove --all`。只剥离工具标记区块，保留其他编辑；直接删除文件夹无法执行清理。

## CLI 可以稍后再接

Agent 可通过 `agent setup --manifest` 直接提交节点配置，无法执行时返回 JSON 供解析。CLI 接口扩充只保存现有调用方案，不自动生成或安装桥接。会话 ID 和会话记录位置不等于可调用接口，具体宿主应调查其帮助和真实入口，不先启动模型。

探针与连接图保留在高级能力中。真实探针可能收费，需要机器回执及用户确认会话可见；同会话续接另测。原有 CLI/MCP 消息自动投递仍独立保留，不等于新文件对话框有自动模式。旧任务继续原协议。

关闭全部进程后没有后台监控。真实宿主接入、系统通知弹出、显示缩放和迁移的人工体验应分别记录，模拟桥接不作真实兼容证据。
