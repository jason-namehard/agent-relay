# Agent Relay — 第一次任务

版本：`0.1.0-preview.15`。Windows 完整包从 [Release](https://github.com/jason-namehard/agent-relay/releases/tag/v0.1.0-preview.15) 下载并完整解压，运行 `gui/AgentRelay.Desktop.exe` 配置真实 Agent。`TryDemo.cmd` 是隔离演示，会禁止真实 CLI 调用；已在演示中登记资料，可在设置保留当前数据并转为正式使用。GUI/通知自带运行库，CLI/MCP 需要 .NET 10 runtime；保留随包许可证。

## 直接发起 CLI 任务

1. 在 Agent 管理为 A、B 登记调用方案。可使用“一键配置”，也可按字段手动填写程序、参数和输出格式。
2. 在任务看板点击“新建 CLI 任务”，选择 A 及其来源会话，再选 B。目标可以新建会话，也可以从列表明确选择已有会话，不按最近一条猜测。
3. 直接写要完成的工作，不必先找 A 生成交接 JSON 或文件。需要 B 处理、A 审阅、B 落实时，勾选“接收方 → 发送方 → 接收方”；单步任务不勾选。
4. 若所需方向未启用，明确允许启用后，点击“创建并通过 CLI 发送”。这会真实调用宿主，可能产生模型费用。
5. 看板记录当前处理者。回执推动工作及计划：审阅后仍有 B 的落实步骤，不能仅凭 A 的 `needs_reply:false` 提前结束；中间回传必须有真实回稿和具体下一步。

双方会话绑定一次，后续同任务精确续接。若来源或目标不再存在，软件要求重选；结果不确定时先检查真实会话，不自动重发。

## 手动交接已有文件

1. 在 Agent 管理点击“一键配置”，把提示词粘贴到目标 Agent 的新对话，让它直接登记；对 A、B 分别执行。每次配置为独立新建请求，不覆盖已选节点。也可“新建 Agent”按字段填写，只需一个名称，CLI 暂时留空也可使用。
2. 可选安装交接规则：选中节点，展开“交接规则与节点详情”，选择该宿主实际加载的 `AGENTS.md`、`Agent.md` 或其他指令文件，查看规则并确认。常驻只有一行，详细说明按需读取；触发依赖宿主遵从，已有会话可能需重新读取指令。
3. 对 A 说清“写什么文件给谁”。装有规则时 A 可直接返回交接 JSON；未装时，把“新建交接 → 复制交接格式”附在要求后面。
4. 将 A 的 JSON 粘贴进新建交接，点击“解析并创建交接”。也可手动选择发送方、接收方、已存在文件及一句工作要求。
5. 已配置 CLI 时，选择目标“新建会话”或“使用已有会话”。已有会话由你明确选择一次，之后同任务往返自动使用准确 ID；剪贴板无法提供 A 的来源身份，要自动回传可为 A 也选一次。已登记调用方式且 A → B 方向启用时自动发送，否则点击“复制提示词给 B”。
6. 软件运行时自动读取回执变化，启动或刷新补读。如果 B 结束工作且不需 A 继续，任务完成；如仍需 A 处理，软件按反向设置自动发送或明确提示复制给 A。无需导入已完成回稿。

交接 JSON 使用已登记 ID 或唯一名称，文件必须真实存在且为完整路径。完整格式见 [配置与回执](CONFIGURATION_ASSISTANT.md)。

“选择已有会话”先显示缓存，同时只刷新该 Agent 的宿主数据；列表不会自动选中“最近”或第一项。标题、时间和项目路径帮助识别会话，执行续接前再核实记录存在。失效时在任务详情“会话”中更换，不自动跳到其他对话。没有发现能力时可手动保存准确 ID，但未能核实存在的会话不会自动调用，手动复制始终保留。详见[会话管理](SESSIONS.md)。

## 看懂状态

| 状态 | 下一步 |
| --- | --- |
| 等待某个 Agent 接收并回复 | CLI 符合条件时自动发送，否则复制给显示的接收方 |
| 某个 Agent 已接收/正在处理 | 等它写回执，不重复创建任务 |
| 等待对方继续 | 按显示的下一步工作自动投递或复制给该 Agent |
| CLI 投递结果不确定 | 先检查目标会话，避免重复投递 |
| 已完成 | 无需礼貌回传或重复确认 |
| 失败、超时或达到轮次上限 | 查看原因，人工判断是否重建 |

交接计划规定必须完成的步骤，`needs_reply` 表示除此以外是否仍有必要工作。中间步骤不能被提前的完成声明跳过，缺少回稿或下一步会提示补齐。无计划任务仍可在 `done + needs_reply:false` 时结束，但同时写下一步待办会被拒绝。最多四轮，防止反复确认或闲聊。文件改变不等于完成，只有有效回执才改变处理状态。

不再需要的任务可取消，或点击“删除任务”并确认后删除记录。文件保留到后续清理。也可人工“标记交接完成”，软件记录用户决定，不能据此证明 Agent 已完成工作。这些操作不终止已经启动的 Agent。

## 文件、迁移与卸载

外部交接文件复制进受管目录，原件保留；已受管文件直接复用，不再制造正文包装文件和重复结果快照。任务上下文与回执位于隐藏 `.relay` 子目录。最终成果仍应放在项目目录，过期受管文件通过清理操作删除。

迁移前必须完成或取消全部活动任务，包括等待对方继续的回传。更换中转站会复制当前站点文件与账本，校验后切换；保留日期沿用，旧站仅作备份，不会自动清理旧站。没有待完成迁移时，“迁移校验”会说明未发起迁移，不代表刚刚迁移成功。失败后解除文件占用，再用迁移校验继续。

稳定的按需指引入口在迁移后更新；已复制出去的旧短提示需要重新复制。删除便携软件前，先在设置“移除全部交接规则”，或执行 `relay --home <目录> guidance remove --all`。只剥离工具标记区块，保留其他编辑；直接删除文件夹无法执行清理。

## CLI 接入与可选诊断

一键配置通过 `agent setup --manifest` 直接提交节点资料，再导入可用调用方案。接口无法执行时可按字段手动配置，不需要粘贴一整段配置。CLI 方案允许原生 JSON、JSONL 或最终文本，由 Relay 适配；会话 ID 和日志位置不等于调用方式，调查应依据帮助和真实入口。

“Agent CLI 测试”是可选诊断，真实调用可能收费，不是自动交接的硬性前提。登记调用方式并启用方向后可投递；已有会话续接独立检查准确 ID 和实际存储。绿点表示有方案、红点表示探针失败、灰点表示无方案，悬停显示诊断状态。可见性未知不等于不可续接；旧消息任务保留原协议。

若宿主提示“Select a model before sending a message”，先在宿主中为新会话配置模型，或选择已配置模型的已有会话。Relay 不替你猜模型，也不把模型/思考强度塞进任务正文。精确续接默认继承原对话设置。

## 托盘

点击最小化按钮会保留在任务栏，不进入托盘。首次点击右上角 × 会询问一次：缩小至托盘或直接退出；选择保存在“关闭时最小化到托盘”。以后只有 × 按此设置隐藏或退出，不重复询问；取消勾选后直接退出。托盘只有“打开”和“退出”，“退出”始终关闭程序。

## 桌面提醒与提示音

在设置启用桌面通知，可为等待处理、回传、完成或失败显示提醒。同一批次同一任务的事件合并，避免重复刷新反复弹出。升级后使用当前安装包的通知程序，不再依赖旧版本的临时路径。

提示音可选无声音、默认、信息、警告和错误，支持试听；“测试通知”不创建业务任务，也不调用模型。软件运行时直接显示带“应用内通知”标记的右下角提醒，Windows 通知中心可用时静默记录，避免双重横幅；系统记录失败会明确说明。

全部进程退出后没有后台监控。真实宿主接入、系统通知弹出、显示缩放和迁移的人工体验应分别记录，模拟桥接不作真实兼容证据。
