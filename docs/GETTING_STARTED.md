# Agent Relay — 第一次任务

版本：`0.1.3`。Windows 安装版通过开始菜单启动；便携版请解压后运行 `gui/AgentRelay.Desktop.exe`。`TryDemo.cmd` 提供隔离演示，不会调用真实 Agent。中转站的数据独立于安装目录；卸载时默认保留，可选择清除配置与任务记录。

## 创建自动传递任务

1. 在 Agent 页面登记发送方和接收方：从“新建 Agent”菜单选择一键配置或手动填写。
2. 在任务页面的“新建任务”菜单中选择“新建自动传递任务”。填写工作正文，选择双方及所需会话。已有会话需要明确选择；没有发起方来源会话时，交给发起方的步骤需要手动复制。
3. 可选择单次交接，或持续修改与验收。持续验收时指定最终验收方，并手动填写具体标准或让发起方 Agent 拟定。验收上限为 0 时不设上限；无进展暂停和单轮时限仍然生效。Relay 将标准交给验收方，按其回执推进，不独立验证工作质量。
4. 明确允许所需方向后创建任务。自动发送前需要调用方案和相应能力验证；真实调用可能产生模型费用。
5. 看板显示当前处理者和下一步。结果待确认时先检查真实会话，不要重复发送；最终验收方通过且无未解决问题后，新建验收任务结束。

## 创建手动传递任务

1. 在“新建任务”菜单中选择“新建手动传递任务”，指定发送方与接收方，填写要发送方完成的工作正文。
2. 复制完整提示词发给发送方，将它返回的 JSON 粘贴至窗口并解析创建；也可以选择已有文件。
3. 按任务提示复制提示词给当前接收方。Agent 写入回执后，软件运行时自动读取；必要时点击刷新。需要继续处理时按提示传给下一方，整项任务明确完成后才结束。
4. 可选安装一行交接规则到该宿主实际读取的指令文件。规则需用户确认，详细指引按需读取；是否触发取决于宿主。

交接 JSON 使用已登记 ID 或唯一名称，文件必须真实存在且为完整路径。完整格式见 [配置与回执](CONFIGURATION_ASSISTANT.md)。

“选择已有会话”先显示缓存，同时只刷新该 Agent 的宿主数据；列表不会自动选中“最近”或第一项。标题、时间和项目路径帮助识别会话，执行续接前再核实记录存在。失效时在任务详情“会话”中更换，不自动跳到其他对话。没有发现能力时可手动保存准确 ID，但未能核实存在的会话不会自动调用，手动复制始终保留。详见[会话管理](SESSIONS.md)。

## 看懂状态

| 状态 | 下一步 |
| --- | --- |
| 等待某个 Agent 接收并回复 | CLI 符合条件时自动发送，否则复制给显示的接收方 |
| 某个 Agent 已接收/正在处理 | 等它写回执，不重复创建任务 |
| 等待对方继续 | 按显示的下一步工作自动投递或复制给该 Agent |
| CLI 投递结果不确定 | 先检查目标会话；确认未收到后点“确认未收到 · 允许重发”，可再发送一次 |
| 已暂停 · 等待你决定 | 查看原因（轮数用完、单轮超时、无进展、Agent 失败），选择继续、取消或标记完成 |
| 已交付或已完成 | 无需礼貌回传或重复确认 |
| 失败或超时 | 查看原因，人工判断是否重建 |

单次交接由 `needs_reply` 表示是否仍有必要工作：`done + needs_reply:false` 时结束，同时写下一步待办会被拒绝；默认 4 轮用完后暂停，交给你判断。持续修改与验收由回执的 `outcome` 推进：作者提交，验收者要求修改或通过，作者确认接受即交付。作者重交相同文件或验收者重复相同问题时暂停为“无进展”。继续时可附一句说明，轮数用完需追加轮数；超时轮次的迟到回执仍会被接受并恢复任务。文件改变不等于完成，只有有效回执才改变处理状态。早期版本创建、带固定交接计划的任务仍按原计划完成。

不再需要的任务可取消，或点击“删除任务”并确认后删除记录。文件保留到后续清理。也可人工“标记交接完成”，软件记录用户决定，不能据此证明 Agent 已完成工作。这些操作不终止已经启动的 Agent。

## 文件、迁移与卸载

外部交接文件复制进受管目录，原件保留；已受管文件直接复用，不再制造正文包装文件和重复结果快照。任务上下文与回执位于隐藏 `.relay` 子目录。最终成果仍应放在项目目录，过期受管文件通过清理操作删除。

迁移前必须完成或取消全部活动任务，包括等待对方继续的回传。更换中转站会复制当前站点文件与账本，校验后切换；保留日期沿用，旧站仅作备份，不会自动清理旧站。没有待完成迁移时，“迁移校验”会说明未发起迁移，不代表刚刚迁移成功。失败后解除文件占用，再用迁移校验继续。

稳定的按需指引入口在迁移后更新；已复制出去的旧短提示需要重新复制。Windows 安装版可在系统“设置 → 应用 → 已安装的应用”中卸载 Agent Relay。卸载时可选择保留数据、只移除已登记的规则，或移除规则并清除当前站点的账本和偏好；账本包含 Agent 配置和任务记录，清除不可撤销。工作区文件与站点中其他文件保留。仅当前站点的规则可自动清理；便携版可在设置中选择“移除全部交接规则”，或执行 `relay --home <目录> guidance remove --all`。

## CLI 接入与验证

一键配置通过 `agent setup --manifest` 直接提交节点资料，再导入可用调用方案。接口无法执行时可按字段手动配置，不需要粘贴一整段配置。CLI 方案允许原生 JSON、JSONL 或最终文本，由 Relay 适配；会话 ID 和日志位置不等于调用方式，调查应依据帮助和真实入口。

手动“通过桥接发送”只需登记调用方式并启用方向。自动投递还要求对应能力已验证：“Agent CLI 测试”通过（Agent 须写出标记文件）并确认会话可见，或一次真实交接经该方案送达且 Agent 写回了回执。测试真实调用可能收费。登录被拒、未选模型或缺少工具权限会停止该 Agent 的自动投递，处理后在 Agent 管理点击“我已处理 · 允许自动发送”。已有会话续接独立检查准确 ID 和实际存储。绿点表示有方案、红点表示探针失败、灰点表示无方案，悬停显示诊断状态。可见性未知不等于不可续接；旧消息任务保留原协议。

若宿主提示“Select a model before sending a message”，先在宿主中为新会话配置模型，或选择已配置模型的已有会话。Relay 不替你猜模型，也不把模型/思考强度塞进任务正文。精确续接默认继承原对话设置。

## 托盘

点击最小化按钮会保留在任务栏，不进入托盘。首次点击右上角 × 会询问一次：缩小至托盘或直接退出；选择保存在“关闭时最小化到托盘”。以后只有 × 按此设置隐藏或退出，不重复询问；取消勾选后直接退出。托盘只有“打开”和“退出”，“退出”始终关闭程序。

## 桌面提醒与提示音

在设置启用桌面通知，可为等待处理、回传、完成或失败显示提醒。同一批次同一任务的事件合并，避免重复刷新反复弹出。升级后使用当前安装包的通知程序，不再依赖旧版本的临时路径。

提示音可选无声音、默认、信息、警告和错误，支持试听；“测试通知”不创建业务任务，也不调用模型。软件运行时直接显示带“应用内通知”标记的右下角提醒，Windows 通知中心可用时静默记录，避免双重横幅；系统记录失败会明确说明。

全部进程退出后没有后台监控。真实宿主接入、系统通知弹出、显示缩放和迁移的人工体验应分别记录，模拟桥接不作真实兼容证据。
